## Ограничения проверок

- Полного Xcode нет: `swift test` остановился на `no such module XCTest`, Xcode build/test не запускался. XCTest target и CI workflow добавлены, CI не запускался/не пушился. SwiftPM Release и самостоятельные guards действительно проверены.

- После изменения ad hoc-подписи может потребоваться повторный доступ для окончательной копии. В этой сессии пользователь явно разрешил адресный сброс разрешения Voicex и попросил агента включить доступ. После сброса штатным tccutil переключатель включён через системный UI; защиты не отключались.
- Синтетическое Control+Shift+Space через Computer Use из пустого TextEdit не запустило сессию. Причина не установлена; физический глобальный хоткей НЕ объявляется проверенным. Нужна проверка клавиатурой пользователя.
- Начальный конфликт сохранённого code requirement и текущей ad hoc-подписи устранён адресным сбросом разрешения Voicex и повторным включением по прямому указанию пользователя. Внутри приложения проверка AX теперь подтверждает доступ; пользователь физической клавиатурой подтвердил запуск правым ⌘ из TextEdit, появление панели и вставку текста.
- Пока не выполнена полная ручная приёмка: холодный запуск GUI при физически отключённой сети; живые RU/EN фразы; toggle/hold/autorepeat и собственная комбинация физической клавиатурой; вставка в TextEdit, Notes, Safari/Chrome textarea и VS Code; смена поля во время compute и защищённое поле; отмена реального compute, сон/отключение устройства и пяти-минутная запись.
- Проверки guards не заменяют эти системные сценарии. Без подтверждённой цели приложение сохраняет результат для Copy. Команда Cmd+V не гарантирует принятие текста конкретным редактором.

## Ручной сценарий завершения

1. Установить из DMG в Applications; вручную разрешить запуск и системные доступы.
2. Сфокусировать нейтральное поле TextEdit; нажать ⌃⇧Space, произнести нейтральную фразу, остановить и проверить вставку без Enter и сохранение фокуса/HUD.
3. Повторить в режиме удержания, с пользовательской комбинацией, на RU/EN и Auto.
4. Во время распознавания сменить поле/приложение: вставки быть не должно. Проверить защищённое поле и отключённый Accessibility.
5. Проверить тишину, короткую запись, Escape/крестик, sleep, изменение устройства, auto-stop на пяти минутах.
6. Отключить сеть вручную и перезапустить: модель должна загрузиться, распознавание работать. Повторить Copy и остальные редакторы.

## Исправление фонового режима

- В установленной пользовательской конфигурации выбран «Правый ⌘», а проверка Accessibility возвращает отказ. Согласно `NSEvent.h`, глобальные key-related события требуют Accessibility; локальный monitor поэтому работал только внутри Voicex.
- Добавлена явная подсказка с запросом доступа и переходом на стандартную комбинацию. Computer Use подтвердил отображение подсказки, переключение на ⌃⇧Space и возврат на выбранный правый ⌘. Доступы агент не включал.
- Проверка разрешений теперь работает и в фоне. После изменения доверия обработчик подключается автоматически; одинаковая конфигурация не пересоздаёт его и не сбрасывает held state. Новые проверки blocked→trusted, стандартной комбинации без AX и отключённого/приостановленного хоткея прошли в самостоятельных Swift checks. XCTest по-прежнему требует полного Xcode.
- У nonactivating HUD установлен уровень statusBar, скрытие при деактивации выключено, переходы между Spaces/full-screen разрешены, получение фокуса и участие в цикле окон запрещены. Сборка и подпись проходят, установленная копия обновлена.
- Пользователь повторно включил доступ и удалил/добавил запись Voicex. Проверка после полного завершения и нового запуска всё ещё возвращает отказ. Журнал TCC для собственного bundle ID подтверждает `Failed to match existing code requirement`: сохранённая подпись отличается от текущей. Защиты и проверка AX не обходятся. После отдельного явного согласия пользователя выполнен `tccutil reset Accessibility io.github.a-shorokhov.voicex`. По его прямому указанию доступ включён через системный UI. Проверка внутри приложения подтвердила AX-доверие, предупреждение исчезло без перезапуска.
- Пользователь физической клавиатурой подтвердил сценарий в TextEdit: правый ⌘ запускает панель поверх другого приложения, повторное нажатие завершает диктовку, текст вставляется. Это пользовательская ручная проверка; отдельный правый модификатор через Computer Use не поддерживается. Другие редакторы, hold и оставшиеся системные сценарии пока не объявляются проверенными.
- Добавлен `Scripts/install-local.sh`: отказывает при работающем Voicex, проверяет подпись и bundle ID существующей копии, устанавливает целый bundle с откатом при ошибке. Это предотвращает обновление бинарника живого процесса, но не подменяет выдачу системных разрешений. Проверены синтаксис zsh и отказ при запущенном Voicex; отдельная успешная установка именно этим скриптом не прогонялась. Ранее текущая копия установлена целым bundle с сохранением прежней копии.
