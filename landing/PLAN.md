# Voicex — подробный план сайта

## 1. Цель и границы

Посетитель понимает назначение Voicex, системные требования, локальную обработку и шаги установки, затем скачивает доступный установщик. Нет регистрации, кабинета, платежей, API, формы ожидания и облачной диктовки.

Стек: статические HTML-страницы, обычный CSS, немного TypeScript, Vite и npm. Основной текст присутствует в HTML; JavaScript нужен только при появлении реального интерактивного поведения. Не добавлять SPA-router или frontend framework.

Дизайн отложен по решению пользователя. На первом этапе — простая адаптивная вёрстка со стандартной типографикой, без фирменных иллюстраций, дизайн-системы и анимаций. Функциональная готовность и дизайнерская доводка — отдельные результаты.

## 2. Информационная структура

### Главная — index.html

Порядок содержания:

1. Краткое описание: «Диктуйте текст на Mac. Распознавание работает локально».
2. CTA «Скачать для macOS» или «Релиз готовится».
3. Apple Silicon M1+, macOS 14+, русский интерфейс.
4. Как работает: установить модель → выбрать поле → начать запись → сказать текст → остановить → получить расшифровку.
5. Возможности MVP: RU/EN, два режима горячей клавиши, локальный Whisper, вставка и ручное копирование.
6. Локальная обработка: сеть нужна для получения приложения и модели, после установки диктовка работает офлайн.
7. Первый запуск: Microphone, Accessibility и установка модели.
8. FAQ.
9. Повторный CTA.
10. Ссылки на установку, приватность и разрешённый публичный канал поддержки.

Не ссылаться на private GitHub как на доступную всем документацию или поддержку. До появления публичного канала достаточно страниц самого сайта. Не добавлять контактные данные, которых пользователь не предоставлял.

FAQ должен отвечать: какие Mac поддерживаются, зачем скачивать модель, нужен ли интернет, какие языки проверяются, какие разрешения нужны, почему вставка иногда требует копирования и почему macOS предупреждает о первой сборке.

Не использовать выдуманные отзывы, логотипы клиентов, скорость «в N раз», обещание поддержки любого приложения и будущие возможности вроде LLM-редактирования.

### Установка — install.html

Шаги: скачать DMG → открыть → перенести Voicex.app в Applications → запустить оттуда → при необходимости вручную разрешить запуск через Privacy & Security → выдать Microphone → выдать Accessibility → нажать «Установить модель» → дождаться подготовки → проверить диктовку.

Описать первый DMG честно: без Developer ID и нотариализации. Использовать инструкцию Apple; не предлагать отключение Gatekeeper для всей системы.

Диагностика: недоступен хостинг модели, отсутствует интернет/место, отказано в разрешении, занята горячая клавиша, текст распознан, но не вставлен, модель подготавливается, app запущен из DMG.

### Приватность — privacy.html

Отразить фактическое поведение: аудио и распознавание на устройстве; сервер разработчика не получает аудио/текст; нет постоянной истории; последний результат в памяти; вставка использует системный clipboard; модель и токенизатор загружаются с внешнего хостинга; настройки локальные; нет аналитики и автоматических crash-report.

Поведение хостинга сайта описать отдельно после выбора хостинга. Не обещать отсутствие обработки IP внешним провайдером. Не вставлять юридический шаблон с несуществующими функциями или сертификациями.

## 3. Техническое устройство

Три настоящих HTML-entrypoint. Общий CSS и маленький модуль конфигурации релиза. Нативный details для FAQ, если нужны раскрывающиеся ответы. Не добавлять JS-библиотеку ради одного раскрытия.

Конфигурация релиза содержит available, version, downloadURL, checksumURL и при наличии публичный releasesURL. Начальное состояние available=false. В этом состоянии не должно быть активной ссылки на отсутствующий или закрытый файл.

Все CTA используют одну конфигурацию. Ссылка скачивания должна быть доступна посетителю без GitHub-доступа. На телефоне/Windows остаётся пояснение, что установщик для Mac; не писать сложное определение архитектуры браузером.

Сборка выдаёт dist. Для сохранения исходного Pages-направления проверить base `/voicex/`; размещение под другим префиксом должно меняться одной настройкой Vite. Межстраничные ссылки должны сохранять base. Метаданные title/description/lang задаются в каждом HTML.

## 4. Приватный репозиторий и публикация

Текущий repo private. Бесплатный GitHub Pages для него не подходит, приватные Releases не дают публичной загрузки. Это внешний блокер публикации, а не блокер разработки.

Сделать локальный preview и переносимую production-сборку. Не менять repo на public, не создавать второй repo и не подключать платный план самостоятельно. Варианты будущей публикации перечислены в корневом PROJECT.md.

CI первого этапа проверяет npm ci, TypeScript и build. Workflow не должен автоматически пытаться включить недоступный Pages. После выбора Pages добавить отдельную публикацию dist, permissions Pages/OIDC, environment и одну группу concurrency. Никогда не публиковать корень репозитория.

## 5. Реализация и приёмка

1. Создать минимальный Vite vanilla-ts проект, сохранив существующие .md.
2. Настроить три entrypoint и base.
3. Написать содержание и базовый CSS.
4. Добавить конфигурацию недоступного релиза.
5. Проверить direct navigation, отсутствие JS, клавиатуру и разные размеры окна.
6. Добавить build-only workflow.
7. Обновить README реальными командами.
8. Передать интеграции результат и зависимость публичного скачивания.

Проверки: npm ci, check, build, browser preview; ширины 375/768/1440; index/install/privacy открываются напрямую; нет сломанных внутренних ссылок и секретов; базовый текст без JS; состояние CTA соответствует реальности. Полный acceptance-list в MVP.md.
