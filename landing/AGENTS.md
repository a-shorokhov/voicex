# Landing agent

Уточнения пользователя: делай локальные Git-коммиты после крупных завершённых изменений сайта; мелкие правки можно накопить без отдельного коммита. Декоративные анимации зацикливай автоматически; не добавляй ручные переключатели воспроизведения/паузы. Системную настройку уменьшения движения учитывай без отдельного UI.

Рабочая область: `landing/**`. Единственное разрешённое исключение — `.github/workflows/landing.yml`, когда появится рабочая сборка. Прочитай корневые `AGENTS.md` и `PROJECT.md`, затем локальный `MVP.md`.

- Модель: GPT-6.1 Sol, Medium. Ветка: `feat/landing-mvp`, отдельный worktree при параллельной работе.
- Стек: HTML, CSS, TypeScript, Vite, npm. Без React/Next.js, UI-kit, Tailwind, CMS, API и базы.
- Основное содержание должно быть в HTML и читаться без JavaScript.
- Страницы: `index.html`, `install.html`, `privacy.html`; без SPA-router.
- Дизайн пока не согласовываем: только функциональная адаптивная базовая вёрстка.
- Репозиторий private. Не включай Pages, не меняй видимость и не публикуй сайт без отдельного разрешения. Подготовь переносимую сборку; публичное размещение — внешний этап.
- Download URL и доступность релиза — в одной небольшой локальной конфигурации. До реального публичного DMG показывай «Релиз готовится».
- Не обещай работу во всех приложениях, переписывание речи, отсутствие любых сетевых обращений и неподтверждённые цифры.
- Не добавляй формы, аккаунты, оплату, аналитику, выдуманные отзывы и чужие логотипы.
- Не редактируй `application/` и root-документы. Изменение общего контракта сообщи задаче интеграции.

После создания проекта добавь `npm run check`, `npm run build`, `npm run dev`, `npm run preview`. Проверяй `npm ci`, TypeScript, production build и страницы в браузере, включая base `/voicex/`. Большая тестовая инфраструктура для статического содержания не нужна.

Не реализуй roadmap из `PLAN.md`. В конце дай URL локального preview, результаты проверок и внешние блокеры публикации.
